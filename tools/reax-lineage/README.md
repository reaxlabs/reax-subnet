### Exit codes and the `error_kind` of a run that ends without a result (v1.5.0)

| exit | stdout | meaning |
|---|---|---|
| 0 | `{"result": ..., ...}` (and `--out result.json`) | the check ran to the end (any classification) |
| 2 | one JSON line `{"error": <text>, "error_kind": <kind>, "http_status": <int or null>}`, **never a traceback** | the run ended without a result and says why |
| 1 | a traceback on stderr | a bug of the checker (please report; the intake service treats it as `crash`) |

| `error_kind` | when | what the caller does |
|---|---|---|
| `repo_unreadable` | a repo, revision or file cannot be read by us: **HTTP 401 / 403 / 404 / 410 / 416 / 451** (private, gated, missing, removed) or any other 4xx except 408 / 425 / 429; a directory that is not a repo; an implausible safetensors header | not a reason to refuse or correct an entry (RULES 2.7); keep it in intake, retry at a low rate, alarm the operator (the miner may make the repo public) |
| `transient` | **HTTP 429 / 5xx / 408 / 425**, a timeout or connection error after all retries (10 tries with back-off), an answer that is not JSON, a server that ignores range requests. **Since v1.5.1 this also ends the run when it happens inside Tier B, the repo-evidence scan (listing, file reads, id lookups), the start repo / config / tokenizer reads or the entry's own config / tokenizer read** (those steps used to turn it into a note, a skipped comparison or a NEEDS_CORRECTION) | try again later; never refuse or correct |
| `check_error` | the checker refused to run on its input (`CheckError`) | operator |

`http_status` is the last HTTP status seen (null for timeouts / local problems). The text carries no query strings (presigned URLs carry signatures). `fingerprint` ends the same way. 401 / 403 / 404 / 410 / 416 / 451 are final at the first answer (no retries); 429 and 5xx are retried first.

### Holder ids (v1.5.0, RULES 2.9)

The checker derives **no** holder id from a repo id. The entry's holder ids are exactly the `--holder ID` values the caller passes (repeatable: the coldkey, `hf:<account>` for every Hugging Face account linked through an entry that **passed** intake and whose lineage record names the committing hotkey, also through a chain of such links; ids compare case-insensitively). The other side comes from the comparison DB: the `holder_ids` of each model's index record (written by whoever builds the DB: the intake service for entries, the baseline builder for public models, e.g. `["hf:<account>"]`; a model without `holder_ids` belongs to nobody). A commitment of someone else's repo therefore creates no link: a copy of that account's earlier model is `copy_undeclared` (3.8(a), a human decides), not a `duplicate`, and that account's earlier models are weight overlaps of the entry, not own work. `--auto-hf-holder` (default off, never set by the intake service) restores the v1.4.1 derivation of `hf:<owner of the repo id>` on both sides for manual use.

**v1.5.1, RULES 2.9 last sentence:** for the entry's OWN check, `hf:<account of the entry's repo id>` is added to the entry's own holder ids **exactly when the record names the committing hotkey** (`record.hotkey == --hotkey`, the same exact comparison as the record check; no `--hotkey` means it cannot be established, so nothing is added), so a first entry (only its coldkey is known, no entry has passed yet) counts its own account's earlier public models as own work. Never for other models' ids (those come from the DB's `holder_ids` only), never when the record does not name the committing hotkey. A record that names another hotkey than the committing one is a NEEDS_CORRECTION `hotkey` at the record step, before any weight is measured. Method: `Check.own_holder_ids(rec)`, `Check.record_names_hotkey(rec)`. Caveat for the rules: a signed correction names the hotkey of whoever signs it, so a stranger who committed someone else's repo and then sends a correction naming themselves gets the repo's account as "own" too (CHANGES.md item 30).

`--no-tier-b`: a failed frame check then ends as NEEDS_CORRECTION "manual review", never PASS. `--hub-dir DIR` = offline hub (DIR/org/name/rev/).
Result JSON = LINEAGE-PROCEDURE section 9 plus `weight_overlaps`, `joint_share` (information, no verdict), `config_text_only_export`, `weights.layer_map`, `blas_gflops`, `notes`; it never contains the sealed Sample B seed (only its sha256).
Intake state feed schema: `schema/intake-state.schema.json` (+ example). Record schemas: `schema/reax-lineage.schema.json` (`reax-lineage/2`, published) and `schema/reax-lineage-1.schema.json` (legacy `/1`, read as one parent).

v1.2 (round-2 final lineage rules 3.3 / 3.6 / 3.8, 13 Nov): every detected source of the base family that is **not a copy (3.5), not of your own holder and not in your start chain** is a **weight overlap** - an earlier entry of any start or a public model, found by the whole-model test or by the splice test:

Own-holder entries measured in the weights are left out of the bar list, their ancestors stay (3.6). Evidence and numbers: CALIBRATION.md sections 0b, 7, 15.

## v1.6.0 (round-2 rules d8 / d8b, 14 Nov): declared merges, parents, private comparison set

Spec: RULES-v2 2.2, 2.6, 2.7, 3.1-3.3, 3.5, 3.6, 4.7 (d8 + d8b). Evidence and numbers: CALIBRATION.md section 20; one line per change: `../CHANGES.md` items 33-48. **No threshold value changed** (`thresholds.json` is byte-identical since v1.4.0).

**Record schema `reax-lineage/2`.** `parents` replaces `start`: each parent `{kind: list|entry|own, repo, revision, uid?, share, parents?}`; `from_scratch: true` (with `parents: []`) replaces `start.kind none`. A `reax-lineage/1` record is still read, as ONE parent with share 1 (and takes exactly the code path of v1.5.2: the replays are identical). `kind own` = your own earlier entry or public model; its parents go inside it (`parents`, repo@revision each, no share) so the check can verify that its weights come only from allowed parents. The limits (more than 4 parents, a share below 0.10) are NOT in the schema: the check answers them with REFUSED `parents_rule` (RULES 3.3), not with a schema correction. The licence enum is `Apache-2.0` only (RULES 2.6; MIT / BSD removed in both schemas). `script_sha256` covers both schema files.

**What the check does with several parents** (`parents` has 2-4 items; one parent = the single-start path of v1.5.2, role `start` on the bar list):

| step | rule | result |
|---|---|---|
| parents rule | more than 4 parents, or a share below 0.10 | REFUSED `parents_rule`, nothing else is measured, no penalty |
| record | shares add up to 1 +/- 0.02; no parent twice; the entry is not its own parent | NEEDS_CORRECTION `parent_shares`, `parents_duplicate`, `parent_self` |
| allowed-ness | list parent on the List (use start/both, added before the commitment, not flagged); entry parent: known, PASS, not `void`, not flagged, uid matches, and **another holder's only if it was public at the commitment** (`row.public_at` not later than the commitment, row not `private`) | REFUSED `parent_not_listed`, `parent_not_allowed`, `parent_flagged`, `parent_not_pass`, `parent_void`, `parent_uid`, `parent_not_public` (a /1 record: `start_*`) |
| own parents | provable as yours (a DB row with your holder id, or `hf:<account>` among your holder ids); ITS parents allowed in the same way (path `parents/0/parents/1`); when it is not an entry the check already measured: its change is fitted on its declared parents and each must be found | NEEDS_CORRECTION `parent_not_own`, `own_parent_not_confirmed`; REFUSED as above |
| teachers | an entry of another holder only if public at the commitment (RULES 4.7) | REFUSED `teacher_not_public` |
| one engine template | the parents' configs agree on the architecture fields (`evidence.TEMPLATE_FIELDS`: architecture class, layer structure, sizes, tying, activation, experts ...; NOT rope / window / vocab size; a text-only export of a multimodal parent counts as the same) | REFUSED `parents_template_mismatch` (nothing is measured) |
| config / tokenizer | equal to every parent's apart from declared changes; the same finding against several parents is one reason naming them | NEEDS_CORRECTION `config`, `tokenizer` |
| confirmation | joint non-negative fit of the entry's change from the family root on the parents' changes from the root (`Check.fit_parents`, the `joint_fit` machinery). Every parent: weight lower bound (median over layers - 2 se) > 0 on EVERY sample; a parent that is the root counts with what the others leave. The entry as a whole must be in the frame of the fitted mixture of its parents (frame check against `root + sum u_i (parent_i - root)`, u = fitted weights normalised to 1). A failing frame is tried with Tier B against the parent with the largest weight | NEEDS_CORRECTION `parents_not_confirmed` (one reason per parent, field `parents/<i>`, with the measured weight; or one for the frame, field `parents`), `transform_found` (field `parents`) |
| copy | a merge that is a copy of one of its parents is a copy: it beats `parents_not_confirmed` | REFUSED `copy` / `duplicate` |
| undeclared sources | the entry's change AFTER its parents (the residual of the fit) is measured against every earlier comparison model of the family: weight overlaps, at most 3 on the bar list (`bar_list_max_overlaps`) as before; a declared parent is never an overlap; a head equal to a candidate's that differs from every declared parent's is `head_source` | information / NEEDS_CORRECTION `head_source` |
| bar list | every declared parent (role `parent`, with `declared_share`) and every ancestor of every parent (DB `parents` / `start`, the parents the record names for an own parent): **no cap**; teachers; the (at most 3) overlaps | |

New result keys: `record_schema`, `parents` (per parent: `key`, `kind`, `declared_share`, per sample `weight` / `lower_bound` / `se` / `frame_share`, `measured_weight` and `measured_lower_bound` of the sample with the highest lower bound, `confirmed`, `private` / `public_name` for a private entry), `parent_keys` (record order), `from_scratch`, `parents_fit`, `copy_share.*.vs_parents`; `start_confirmed` of a merge = `{confirmed, multi_parent: true, parents, frame_vs_mixture}`. The bar-list items of an entry with ONE parent keep `role: start`. **What the caller (intake service) must write:** comparison-DB rows of an entry with several parents get `parents: [repo@rev ...]` and `parent_shares: {repo@rev: share}` (the largest-share parent stays in `start`); every row that is an entry gets `public_at` = the time we first saw it public (its reveal) and `private: true` while it is not; `void: true` for a void entry. The check never guesses these.

**Private comparison set (RULES 2.7 / 3.2).** The intake check compares with everything earlier, still-private entries included. **The rows and the fingerprint files of an entry that is still private are sampled weights of a private model and are CONFIDENTIAL: the comparison DB is never published, never exported, and its private rows are deleted with the entry when it becomes void.** `dry-run` (the MCP's `lineage_dry_run`) skips every row flagged `private` (public models and revealed entries only, RULES 3.2). `export-db` writes a copy without the private rows (`ComparisonDB.export_public`). A private entry is named in messages as "a private entry of this round (uid N)"; its structured items (`weight_overlaps`, `sources_detected`, `bar_list`, `top5_nearest`, `parents`) carry `private: true` and `public_name` and still the internal `model` key: **the result JSON of a check that involves private rows is internal; whoever publishes it (the uid page) must show `public_name` and never `model` for these items.**

Limits: a merge entry whose own change is very large biases the SIZE of the fitted weights (they can add up to less than 1) but not their proportions; every declared parent must still have a positive lower bound. Parents of different families in the comparison set use the family root of the parent with the largest share (noted). A declared `layer_map` in a merge inherits the layout of the parent with the largest share. `own_parent_not_confirmed` is a fit on sampled rows like every other measurement here.
